# Топология рига (стойки/Pi/сеть/Lockit) — ресёрч с критиками 2026-07-12

Архитектура оператора: стойка = 8-10 HERO13 → USB-хаб (питание+управление) → Raspberry Pi; стойки связаны WiFi или Ethernet; опция Lockit между стойками. Минимум кабелей.

## Рамка: ВРЕМЯ ≠ ФАЗА (держится везде)

- Синхра ВРЕМЕНИ (общие часы/таймкод → выравнивание файлов ±1 кадр): умеют GPS, QR precision-time, LTC/Lockit, PTP/NTP.
- Синхра ФАЗЫ кадра (genlock, окна экспозиции совпадают): **HERO13 не имеет тактового входа в сенсор → невозможна**. Не решает НИКТО из списка. Единственный рычаг у фазы — момент подачи питания (гипотеза, E9/E10 проверяют).

## Вердикт по Lockit: ПОКУПАТЬ НЕ НАДО

Lockit выдаёт LTC/genlock/word-clock/ACN-радио (0 ppm между Lockit'ами). **Но GoPro не принимает ни genlock, ни word-clock** — только LTC-аудио в Media Mod, и даже он лишь штампует таймкод-трек, не фазирует затвор.
- Lockit → Media Mod на каждую камеру: **$99.99 Media Mod × 8-10/стойка** ради метаданных, которые бесплатно даёт QR/GPS. Отклонено.
- Lockit → Pi: у Pi нет входа genlock/word-clock; ACN — проприетарное радио без приёмника под Pi; максимум LTC-аудио через USB-звуковуху, но точность теряется на хопе Pi→камера.
- **Итог:** Lockit оправдан ТОЛЬКО если уже есть у оператора и хочется привычный мастер ВРЕМЕНИ (один на стойку, никогда на камеру). Покупать новый под этот риг — нет. Он не решает ФАЗУ, а ВРЕМЯ дешевле закрывает GPS/PTP.

## Сеть между стойками: Ethernet, не WiFi

- PTP (IEEE 1588) hardware-timestamping: **Pi 5 / CM5 / CM4 — да** (суб-µs…µs); **Pi 4 — НЕТ** (только software, десятки µs…мс).
- WiFi: аппаратного timestamping нет, NTP ~1-10 мс.
- **Но суб-мс между Pi ИЗБЫТОЧНА**: узкое место — хоп Pi→камера (камера берёт только clock-точность десятки мс QR / ~1 мс GPS, сенсор free-running). Для «±1 кадр старта» (16.7 мс @60fps) достаточно Pi-to-Pi <1 мс — тривиально по NTP/GPS-PPS.
- Практично: GPS+PPS на каждую Pi + chrony (µs от UTC, без Lockit), ИЛИ Ethernet-PTP с грандмастером Pi5/CM4.

## Раздача времени и старт камерам (по USB от Pi)

- Управление: **Open GoPro RNDIS/ECM over USB** — подтверждено, каждая камера = свой HTTP-эндпоинт 172.2x.x.x:8080, Pi+хаб адресует всех. Латентность ~20 мс/камера при последовательных HTTP.
- **Кучнее всего старт: НЕ гонка HTTP, а запланированный общий старт** — выставить всем часы (GPS/QR), затем `!<HH:MM:SS.sss>S` → каждая камера стартует от своих синхронных часов, а не от прихода пакета. Убирает 20 мс HTTP-джиттера. «±1 кадр» реально @30-60fps.
- USB-serial-shell для `oT`/`!S` — у нас РАБОТАЕТ (проверено), но GoPro официально не документирует → закладывать QR как основной, serial как бонус.

## Итоговая топология

| | ДЕШЁВЫЙ путь (рекоменд.) | ДОРОГОЙ (только если Lockit уже есть) |
|---|---|---|
| Между стойками | Ethernet стойка-к-стойке | ACN C-Jam радио между Lockit |
| Бэкбон времени | PTP по ethernet (Pi5/CM4) ИЛИ GPS+PPS на Pi+chrony | 1 Lockit/стойка → LTC в Pi через USB-звук |
| Фаза | нет (пост / высокий fps) | нет (Lockit фазу НЕ даёт) |
| Триггер | Open GoPro USB, запланированный старт | то же |
| Доп. цена | ~$0-50/стойка (ethernet; GPS-HAT $30-50) | ~$550 × N стоек + опц. Media Mod $99.99/кам |

Железо: Pi 5 8GB ~$80; CM4 ~$25-75; powered USB-хаб 10-port ~$30-60; GPS/PPS-HAT ~$30-50.

## 4 вывода

1. Lockit не покупать (решает ВРЕМЯ = дешевле GPS/PTP; не решает ФАЗУ).
2. Между стойками Ethernet + Pi5/CM4 (не Pi4, не WiFi для точности) — но суб-мс избыточна.
3. Триггер = Open GoPro USB с запланированным общим стартом, не HTTP-гонка.
4. Фаза кадра — открытая проблема, топологией не закрывается; рычаг = одновременный VBUS-фронт (E9/E10) + высокий fps + пост.
