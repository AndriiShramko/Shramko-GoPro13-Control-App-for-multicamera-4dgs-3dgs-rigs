# Как командовать inline-устройством без лишних проводов (ресёрч 2026-07-12)

## Главный физический факт (переопределяет всё)

Устройство между хабом и камерой. Команда может прийти ТОЛЬКО с хаб-стороны. И в моменты, когда команда нужна:
- **Камера выключена** (нужно для передёрга/фазировки старта): линии данных МЕРТВЫ — слушать нечего.
- **Камера качает на 5 Гбит/с**: данные идут по SS-парам, USB2 D+/D- ПРОСТАИВАЮТ.

→ Для функций питания единственный wire-free канал команды — **сам VBUS с хаб-стороны**.

## Варианты (оценены)

| Вариант | Реалистичность | Точность | Вердикт |
|---|---|---|---|
| **VBUS power-line** (хаб мигает VBUS, MCU декодирует, живёт на суперкапе) | средняя | грубая (мс, uhubctl) | 2-4 дискретные команды — ГОДИТСЯ |
| Tap D+/D- (пассивно слушать) | слабо (только LS/FS, нужен RP2040; в нужные моменты слушать нечего) | — | ОТБРОСИТЬ |
| Модуль сам энумерируется (CDC+хаб) | дорого (USB3-хаб-IC $3-8, тепло, SS-layout) | команды богатые, но всё равно мс | только если нужен богатый протокол — тогда проще управляемый хаб |
| **Автономный триггер** (реакция на VBUS-фронт + запрограммированный оффсет) | ВЫСОКАЯ, элегантно | µs-джиттер фронта MCU относительно опорника | **ЛУЧШИЙ** — хаб даёт грубый broadcast, MCU добавляет чистый фронт |
| Управляемый хаб (uhubctl PPPS) вместо inline | дёшево, native-команда, 0 на камеру | мс, PPPS часто сломан/ganged | для дешевизны; НЕ даёт µs-фронт |

## ВЕРДИКТ

**Связка: dumb/ganged-хаб (грубый broadcast VBUS) + inline-модуль CH32V003 (реакция на VBUS-фронт + power-line декодер 2-4 команд) + TPS22918 (CT-slew inrush) + суперкап. SS-пары насквозь. Конфиг оффсета — DIP/резистор разово.** Команда = VBUS-паттерн от хаба; точный фронт = MCU локально. ~$1.5-3/модуль.

## ЧЕСТНАЯ ОГОВОРКА (важно, снимает иллюзии)

1. **µs-одновременность 100 устройств ТОЛЬКО по USB — НЕДОСТИЖИМА межстоечно**: USB не имеет общего межконтроллерного такта. µs возможна лишь внутри одного Pi-дерева через SOF (нужен USB-tap = RP2040). Настоящий µs-genlock 100 узлов требует общего физического опорника (PPS/провод) — это «лишний провод».
2. **Даже µs-точный VBUS-фронт НЕ даёт µs-точный кадр**: загрузка GoPro до первого кадра — секунды с джиттером сотни мс; сенсор free-running. Реальный потолок синхры питанием = уровень КАДРА (десятки мс), не µs.
3. **Ценность inline-модуля — НЕ µs**, а: (1) надёжный чистый передёрг каждой камеры (кривой PPPS хаба часто не даёт), (2) детерминированный низкоджиттерный фронт старта в пределах стойки. Проектировать под передёрг + кадровую фазировку, не под мифические µs.

Источники: uhubctl (PPPS кривизна) · GoPro Labs USB Power Trigger · RP2040 PIO USB-sniffer (LS/FS only) · TI TPS22918 (CT-slew).
