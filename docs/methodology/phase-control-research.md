# Трек «Управление фазой кадра» (вопрос Андрия 2026-07-12: старт с точностью 1/10–1/100 кадра)

**Вопрос:** можно ли заставить камеру стартовать так, чтобы кадр был идеально синхронизирован с заданным моментом времени (внутрикадровая точность 1/10–1/100 кадра)?

## Установленные факты (не мнения)

1. Команда старта записи фазу НЕ двигает: сенсор free-running с момента включения/входа в режим; `shutter/start` выбирает границу уже идущего кадра (D. Newman/GoPro labs#1101; Xangle). Штатной команды «сдвинь фазу» не существует ни в стоке, ни в Labs.
2. Программная фазировка доказана на Android (libsoftwaresync, 250 мкс) — там есть API подстройки экспозиции. На GoPro такого API нет.
3. Следствие: путь «какие команды отправлять для фазы» в лоб закрыт. Открыты два обходных.

## Путь А (гарантированный): измерение фазы + компенсация = эффективная синхра 1/100

Фаза каждой камеры на каждом дубле ИЗМЕРЯЕТСЯ (LED-вспышка → полосы rolling shutter, σ 0.3–0.5 мс лит.; наш стенд/scanout — см. E7) и КОМПЕНСИРУЕТСЯ: VFI-ретайминг на общую сетку или per-camera time offset в 4DGS (Sync-NeRF, SyncTrack4D — <0.26 кадра без внешних данных; наши измерения = точный prior). Для зрителя/реконструкции результат неотличим от аппаратной фазировки.

## Путь Б (исследовательская ставка): фазировка моментом ПОДАЧИ ПИТАНИЯ

Гипотеза: фаза = f(момент включения сенсора). Если воспроизводимо — фазой можно УПРАВЛЯТЬ, контролируя момент power-on (Labs USB Power Trigger: камера стартует при подаче питания) с точным железом (реле/управляемый хаб, мкс-тайминг). На 100 камер: подать питание каждой в рассчитанный момент → фазы выровнены.
Неизвестные (наши эксперименты):
- P-Б1: детерминирован ли лаг «питание → первый кадр сенсора» (σ?). Если σ ≥ кадра — путь мёртв.
- P-Б2: сохраняется ли фаза при переключении режимов/пресетов (или каждый вход в режим = новая фаза?).
- P-Б3: температурная стабильность лага.

## E7 — измерение субкадровой фазы БЕЗ Arduino: излом scanout-а монитора

Монитор перерисовывается сверху вниз за один refresh (~6.4 мс на этой панели). Кадр камеры, экспонированный во время перерисовки, содержит ШОВ: выше шва — новый кадр стенда (индекс N), ниже — старый (N-1). Вертикальная позиция шва в строках кадра = момент экспозиции строки относительно scanout → субкадровая фаза с разрешением долей мс.
Реализация: полоса стенда дублируется в 3-5 строках по высоте экрана (верх/центр/низ) → декодируем каждую → у «расколотого» кадра верхние полосы показывают N, нижние N-1 → интерполяция позиции шва между полосами. Разрешение ≈ refresh/число_полос… точнее: шов между полосами i и i+1 локализует фазу в окно (Δy_полос/высота_экрана)×6.4 мс — при 5 полосах ~1.3 мс ≈ 1/25 кадра @30fps; для 1/100 — LED (Ф1).
Эксперименты на ОДНОЙ камере (сейчас):
- E7a: 10 записей подряд БЕЗ power-cycle → фаза первого кадра каждой записи. Гипотеза «старт не сбрасывает фазу»: фазы лягут на одну решётку (mod период кадра) с учётом дрейфа.
- E7b: 10 записей с power-cycle между ними (оператор жмёт кнопку или USB-реле позже) → распределение фаз: равномерное = фаза случайна от включения; кластеризованное = детерминизм есть → путь Б жив.
- E7c: смена режима (видео↔фото↔видео) между записями → сбрасывает ли фазу.
