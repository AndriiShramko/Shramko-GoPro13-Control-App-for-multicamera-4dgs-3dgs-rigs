# Сводный отчёт: синхронизация 100×HERO13 (4K 8:7@59.94) для 4DGS
**Дата:** 2026-07-12. **Цель оператора:** межкадровая точность 1/10–1/100 кадра (1.67–0.17 мс) от дубля к дублю, синхра в железе, калибровка/перезапуск перед дублем — можно, ретайминг — нельзя, дубли ≤5 мин.

## 1. Аудит E9: вердикт

**Вывод E9 «каждый старт записи рандомизирует фазу сенсора» — НЕ ДОКАЗАН.** 2 из 3 рецензентов: verdict не стоит; третий подтверждает лишь узкую форму «фаза между дублями не воспроизводится», но не причинную («рандомизирует») и не стратегическую («путь управляемого старта мёртв»).

### Критические изъяны
1. **Ложная предпосылка о стенде.** Лог `stand-counter-20260712_233652.jsonl`: медиана интервала flip = 6.974 мс (~143–144 Гц панель), p5–p95 = 5.46–15.78 мс, 1.4% интервалов >20 мс. Вся модель ошибки в CONCLUSION.md («квантование 60 Гц», «SE 0.6–0.9 мс») построена на несуществующем режиме.
2. **Алиасинг 59.94/60.00 Гц.** Пила выборки с периодом биения ~16.7 с; дубли шли через ~11.6 с → интерцепт получает своё квазислучайное смещение на каждый дубль. Даже идеально непрерывная фаза выглядела бы «прыгающей».
3. **Нулевая статистическая мощность.** n=10: Rayleigh R≈0.39, p≈0.22 — равномерность не отвергнута и не подтверждена. Наблюдаемая circ-σ 3.66 мс = 23-й перцентиль равномерного нуля (Монте-Карло). Бенчмарк «4.82 мс» некорректен: это линейная σ, сравнённая с циркулярной.
4. **SE интерцепта занижен в 2–3 раза.** Без leverage-члена (интерцепт на краю окна x∈[0,4] с): реально 0.65–2.18 мс на дубль, и это нижняя граница (остатки не iid). Фраза «скачки 8 мс реальны» не обоснована.
5. **Структура данных против равномерности:** 7/10 фаз в окне 3.0 мс (6.75–9.77); три «выброса» отстоят от среднего на −7.83/+7.58/+5.79 мс ≈ один интервал flip (~7 мс) — сигнатура мисаллокации индекса декодером, не рандома.
6. **ppm не вычтен:** +14.6 ppm × ~2 мин сессии ≈ 2–3 мс систематического увода — сопоставимо с шириной кластера.
7. **Конфаунд старта:** джиттер HTTP-старта σ=18 мс ≥ периода 16.683 мс → детерминированная фаза f(момент старта) неотличима от рандома на этих данных. t_enc мерился поллингом 50 мс — корреляция фаза↔старт не проверяема.
8. Селекция декода (24–73 точки из ~240), логирование t_before flip, одна камера (межкамерная фаза — то, что нужно оператору, — вообще не измерена).

## 2. Идеи после критики

### МЁРТВЫЕ
- **«Фазовая лотерея с VBUS-пересбросом» (Идея 2, industry)** — оценки критиков 3 и 2 (dead). Причина: **измерение уничтожает измеряемое** — файл недоступен во время записи (Open GoPro не отдаёт незавершённый MP4), значит для замера фазы запись надо остановить, а любой следующий старт (по предпосылке самой идеи) — новый розыгрыш. «Победители продолжают писать» физически невозможно без живого канала фазы, которого нет. Плюс: раунд реально 40–60 с (не 8), дрейф ожидающих камер съедает окно за минуты, сотни power-циклов в смену. Салвидж = путь «непрерывный блок» из CONCLUSION E9.
- **Всё семейство rejection-sampling наследует тот же дефект** (kill-критерий №0: замер фазы БЕЗ остановки записи не продемонстрирован) — Идеи 1/фолбэк живы только условно, см. ниже.

### ЖИВЫЕ (ранжир после критики)

**#1. Строб-генлок 59.94 Гц + затвор 360° + рестич по шву (7.5 / 7.5)** — единственная схема, делающая результат E9 **безразличным**.
- *Механизм:* тёмная площадка, мастер-клок (TCXO/GPS → делитель строго на 60000/1001 Гц) гонит импульсы 100–300 мкс; при shutter 1/60 (360°) каждая строка каждого кадра интегрирует ровно один импульс — время задают фотоны, не кварц камеры. Шов (граница импульсов k/k+1) = бесплатный фазометр ~5 мкс; рестич = перестановка строк, ноль интерполяции; смешанная полоса w/Δ (~40–50 строк) маскируется.
- *Калибровка перед дублем:* 2 с blackout + Manchester-модуляция импульсов (перенос механики `stand.py`/`decode_stand.py`) → привязка кадр↔импульс автоматически; перезапуски камер не нужны вообще.
- *Точность:* межкамерный сдвиг сэмплов ≈ 0 по построению; ширина сэмпла 200 мкс = 1/83 кадра — цель перекрыта с запасом.
- *На одной камере на этой неделе (E13-строб, до любых закупок):* Pico + MOSFET + COB 20–50 Вт, 59.94 Гц из PIO; боевой режим с гейтом (2=108/234=5/3=5), Protune 1/60, ISO/WB lock, HyperSmooth OFF, Wide. Проверить: (а) истинность 360° — искать гэп/мигрирующие тёмные строки (порог годности <~100 мкс), в т.ч. прогон на 60.00 Гц для разделения 1/60.00 vs 1/59.94; (б) один шов на кадр, ширина полосы ≈ w/Δ; (в) протечка temporal-NR: одно-кадровый маркер-вспышка → не просачивается ли в соседний импульс; (г) карта «строка вывода → строка сенсора» для Wide (dewarp!); (д) H.265 у движущегося шва; (е) Manchester из вспышек декодируется.
- *Обязательные правки из критики:* трекинг шва по Manchester-якорям + ppm-модели (на статике шов оптически невидим); светобюджет пересчитать фотометрически ×2–3 запас, дерейтинг перегруза COB ≤3×; N+1 (второй мастер-клок, запасные панели); строб-safety протокол (60 Гц — граница фоточувствительной зоны) + рабочий свет между дублями + e-stop; blackout-чеклист (LED всех 100 камер погасить через Labs); **письменно согласовать с оператором**: перестановка СТРОК (не кадров) = разрешённая «механическая перестановка», и look «ноль моушен-блюра».

**#2. «Кварцевый паспорт» — ppm-метрология + прицел на середину дубля (7 / 5)** — обязательный СЛОЙ для любого пути, не самостоятельное решение.
- *Механизм:* относительный ppm каждой камеры по LED-стробу (наклон фита); упреждение фазы −ppm_i×T/2 половинит ошибку дрейфа. Числа: без компенсации ±15 ppm × 300 с = ±2.25 мс (провал); per-camera компенсация + дубль 60 с → ~±0.06–0.3 мс вклада дрейфа.
- *Критика внесла:* ppm — функция температуры (AT-cut, камера греется на десятки °C в 4K8:7@60) → паспорт снимать только в термо-рабочем состоянии (≥10 мин прогрева записью), гейт σ<0.5 ppm между холодным/горячим; заявку 0.05–0.1 ppm убрать до суб-кадрового декодера (честно 0.3–0.5 ppm); биннинг по стойкам выкинуть как механизм точности (упреждение и так per-camera); QC-маяк (head+tail LED-burst) в каждый боевой дубль с вердиктом ≤5 мин.
- *Калибровка:* 1 час приёмки парка (параллельно) + экспресс-переобмер раз в смену + прицел на середину перед дублем.
- *На одной камере на этой неделе:* 3×5-мин клипа LED-PRN (холодная/прогретая/после VBUS-передёрга) → воспроизводимость ppm (σ<0.5), линейность дрейфа (резидуал <0.1 мс/5 мин), совпадение оптического ppm с PTS-наклоном.

**#3. Оверкрэнк 4K@120 (16:9) + механический выбор ближайшего кадра (6 / 7)** — честный fallback «нулевой церемонии», путь Xangle.
- *Механизм:* фаза любая, на монтаже берётся ближайший кадр к глобальному 60 Гц-тику (перестановка целых кадров — разрешена). Ошибка ±4.17 мс, RMS 2.41 мс = 1/7 кадра средне, 1/4 худший — **НЕ проходит 1/10, нужна письменная приёмка оператора** (SyncTrack4D-порог 0.26 кадра проходит впритык).
- *Жертвы:* 8:7 (на 120 fps его нет) — решение по FOV (портрет/доп. ряд) до проектирования стоек; свет ×2; сторедж ×2; термика 4K120 — главный риск дня.
- *На одной камере на этой неделе:* термотест-циклограмма (5 мин запись / 3–5 мин пауза, 3–4 ч, в корпусе); строб-маяк вместо монитора на 120 fps; гистограмма |ближайший кадр − тик| (равномерная 0..4.17, RMS~2.4); t_enc именно в 4K120 (3.08 с из 8:7 непереносимо); manual lock (shutter/ISO/WB) доступен ли в этом режиме.

**#4. Free-run режим-картирование (5 / 4)** — дешёвый эксперимент, не план съёмки.
- Гипотеза: в режимах без реконфигурации (5.3K@60 — encoding мгновенный) сенсор free-run с бута, фаза постоянна на сессию. Важно: «тёплый конвейер» в 4K8:7@60 фактически уже проверен E9 (режим ставился один раз, дубли подряд — фаза всё равно скачет) — для боевого режима ветка закрыта, живёт только через смену режима (потеря 8:7 — решение оператора ДО теста). Арифметика rejection-выравнивания честно: p=0.10 для окна 1/10 кадра, ~70 раундов, часы; 1/100 недостижим. Дрейф ломает «раз на сессию».
- *На одной камере:* E9-протокол в 5.3K@60 (critеrий circ-σ<0.5 мс + тренд 14.6 ppm) + 20–30 VBUS-ребутов → гистограмма фаз (равномерность/кластеры).

**#5. Rejection sampling с LED-замером (обе версии; 6/5 и 6/5)** — условный fallback, только если E13 покажет неуправляемость И строб не согласован.
- Блокеры из критики: kill-критерий №0 (замер фазы без остановки записи — не существует); дрейф камер ЗА ВРЕМЯ калибровки 4–7 мин съедает окно ±2 мс (обязательно предиктивное упреждение по ppm); честный цикл 12–25 с, калибровка 5–12+ мин/дубль с хвостом; честный потолок 1/8–1/10 кадра; soft-gate «92–95 из 100» + таймаут вместо «все 100»; термо- и SD-износ. Shutter-lock 1/960+ и детекция фронта полосы при съёмочном затворе — недоказанные звенья.

**#6. Строб 119.88 Гц + 180° + per-row время (6 / 5)** — апгрейд #1 сменой константы деления, но: полных кадров не существует ни у одной камеры → материал заложник несуществующего per-row 4DGS-лоадера. Порядок инвертировать: **сначала** микро-прототип лоадера на синтетике (блокирующий milestone), железо всегда с переключением 60↔120 и контрольными дублями в схеме #1.

## 3. Рекомендуемая связка и план

**Стратегия — два трека параллельно + обязательный слой метрологии:**

- **Трек А (основной, независим от исхода E9): строб-генлок 59.94 Гц (#1).** Единственная схема, где синхра существует в фотонах, ноль устройств на камеру, калибровка 2 с без перезапусков. Гейты: E13-строб на одной камере → прототип одной панели с фотодиодом → согласование с оператором (перестановка строк, look, blackout, строб-safety) → закупка.
- **Трек Б (дешёвый, может закрыть задачу электроникой): управляемый старт.** Решается R0+E13: если фаза = f(момента старта) — расписание !S по oT-часам + per-camera ppm-упреждение даёт субкадровую расстановку фаз на 100 камерах без строба вообще; inline-VBUS-устройство остаётся как ребут/Power-Trigger (проверить E10'). Если E13 даст рандом — трек закрывается, остаётся А.
- **Слой (обязателен для обоих): кварцевый паспорт (#2)** — термо-протокол, per-camera упреждение на середину дубля, LED-QC-burst в каждом боевом дубле.
- **Fallback'и:** (а) «непрерывный блок дублей ≤5 мин одной записью + вспышки + известные оффсеты» — валидируется E12, требует согласия оператора, что известные постоянные субкадровые сдвиги достаточны для 4DGS; (б) 120 fps nearest-frame (#3) — только с письменной приёмкой ±4.17 мс.

### План экспериментов по приоритету (эта неделя — всё на одной камере)
1. **R0/R1 — доанализ E9 (сегодня, 0 руб.):** модель пилы + BIC, phase↔t_cmd, Rayleigh/MC, leverage-SE, гистограммы остатков выбросов, детренд ppm. Может опрокинуть/спасти E9 без съёмки.
2. **R2 — ffprobe всех клипов (5 мин):** первый PTS, elst, дельты PTS.
3. **R3 — LED-пробник (блокер всего):** Pico/GPIO, счётчик ~1 кГц / PRN-строб, shutter ≤1/480; критерий SE фазы <0.2–0.3 мс, декод >80% кадров (сейчас 10–30% — диагноз пайплайну).
4. **E13 — управляемость (oT + !S, 24 дубля, шаг 1–2 мс):** R²>0.8 → трек Б побеждает, вся архитектура = staggered-старты; R²<0.2 → трек Б закрыт.
5. **E12 — стабильность внутри записи (3×300 с):** p-p ≤0.5 мс после детренда → fallback «непрерывный блок» сертифицирован на 1/10 кадра.
6. **E13-строб — одно-камерный тест схемы #1** (360°-гэп, NR-протечка, шов, dewarp-карта, Manchester): гейт перед любой закупкой панелей.
7. **E9-diff — двухкамерный дифференциал** (нужна 2-я камера): главный дискриминатор межкамерной фазы.
8. **E10' — VBUS/Power Trigger (15 циклов):** σ(phase−edge)<1.5 мс → inline-VBUS-устройство = актуатор; определяет его конструкцию.
9. **E-mode — карта режимов + термо/ppm-паспорт** (тесты #2 и #4).

**Дерево решений:** E13 управляемость → электронный путь (!S+oT+паспорт), строб = QC/резерв. E13 рандом + E12 стабильно → непрерывный блок с оффсетами (согласовать с оператором) ИЛИ строб. E12 нестабильно / оффсеты неприемлемы → строб-генлок безальтернативен. 120 fps — страховка на подписи у оператора в любом сценарии.
