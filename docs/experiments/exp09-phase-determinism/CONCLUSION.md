# E9: детерминизм фазы кадра — ВЕРДИКТ (2026-07-13, ночь)

## Ответ на вопрос оператора

**«Внутрикадровая синхронизация всегда одна и та же от дубля к дублю или плавающая?» — ПЛАВАЮЩАЯ.**

10 дублей подряд, одна сессия питания, то же внутреннее время, верифицированный режим 4K 8:7@60 (гейт: 2=108, 234=5, 3=5), size-verify скачивания.

## Числа

- Фазы первого кадра по дублям (мс, mod 16.683): **0.76 · 8.06 · 9.11 · 16.17 · 9.77 · 14.38 · 7.00 · 7.65 · 6.75 · 9.17**
- Циркулярная σ = **3.66 мс**; равномерный рандом дал бы 4.82 мс → распределение близко к случайному.
- Ошибка измерения фазы ~0.6-0.9 мс (resid обусловлен квантованием рефреша монитора 60 Гц; SE=resid/√n) → скачки 8 мс между соседними дублями РЕАЛЬНЫ, не шум.
- Скачки не монотонны → это НЕ дрейф ppm (он дал бы ~0.3-0.5 мс/дубль монотонно).

## Что это значит

1. **Каждый старт записи рандомизирует фазу сенсора.** Даже без выключения камеры, даже с идеальными общими часами: `!S`/HTTP-старт не задаёт фазу. Теперь это доказано НАШИМИ данными на НАШЕЙ камере (не только литературой).
2. **Путь Б (фазировка питанием) в исходном виде мёртв**: даже если синхронно подать питание, следующий старт записи снова рандомизирует фазу. Power-cycle тест (E10) этот вывод уже не спасёт — фаза рандомится раньше, на старте записи.
3. **Живой путь для железного субкадра: НЕ останавливать запись.** Фаза случайна В МОМЕНТ старта, но внутри одной непрерывной записи сенсор стабилен (дрейф ~15 ppm = 0.9 мс/мин). Схема: все камеры стартуют ОДИН раз (±1 кадр по часам), пишут весь блок дублей непрерывно (съёмки ≤5 мин — влезает), общая вспышка в начале фиксирует взаимные суб-кадровые смещения. Смещения постоянны на протяжении записи.
4. Требует проверки (E12, одна камера): стабильность фазы ВНУТРИ непрерывной записи 60+ с (ожидание: уходит только на дрейф ppm). Затем Ф1 (2 камеры): дельта фаз двух камер в непрерывной записи.

## Валидность

- Режим верифицирован гейтом ДО записи; fps каждого клипа сверен из файла (59.94).
- 10/10 дублей скачаны с проверкой размера (баг keep-alive/Session убит до прогона).
- enc_delay (encoding=1 после команды) по 10 дублям: 3030-3133 мс — стабильная константа режима (σ≈27 мс), на фазу не влияет (фаза мерится по стенду, не по команде).
- Слабое место: порог 20+ точек/дубль при декоде 8:7 (разброс n=24-73); SE ≤1 мс — на вердикт не влияет.
