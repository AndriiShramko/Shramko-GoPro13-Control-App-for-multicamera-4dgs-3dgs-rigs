# Сводный отчёт главного инженера — стенд синхронизации 100× HERO13

## 1. Монитор как пробник: чинить и использовать, но только как лабораторию

**Вердикт: монитор использовали неправильно, метод не виноват.** Три одновременные ошибки: панель работала на 144 Гц (медиана flip 6.974 мс = 143.4 Гц) при коде под 60; анализ брал метку `t_before` вместо vblank-выровненной `t_after`; экспозиция камеры не лочилась (авто-выдержка ~1/60–1/120 накрывала 2–3 смены кадра → Manchester-violation → выживало 10–30% кадров). Прошлый вердикт «фаза плавает» этим объясняется без мистики.

**Роли после ремонта:** монитор — лабораторная валидация E13/E12 и калибровка декодера (1–3 камеры). LED-риг — боевой стенд на 100 камер, безальтернативно: LCD физически не даст фронт <0.1 мс (G2G 1–5 мс) и не виден 100 камерам по кругу.

### Чек-лист ремонта (порядок = порядок работ)

**А. Система:** (1) панель → 60 Гц фиксировано, VRR/FreeSync off (OSD + драйвер + Windows); (2) в `stand.py` проверка частоты через EnumDisplaySettings, аборт если не 60.000±0.1; (3) `timeBeginPeriod(1)` + HIGH priority.

**Б. Пейсинг:** (4) `DwmFlush()` после flip — **гипотеза №1, не решение** (fullscreen может идти мимо DWM через independent flip); если не помогло — DXGI waitable swapchain / диагностика PresentMon; (5) лог в list, запись на диск после прогона; (6) `font.render` убрать из горячего цикла; (7) первые 5 с — warm-up, выбрасывать.

**В. Валидация каждого прогона (блокирующий gate):** анализ только по `'a'`; критерий годности: медиана 16.67±0.05 мс, доля интервалов вне [16.2, 17.2] мс < 2%; негодный прогон не анализируется.

**Г. Камера:** Protune shutter lock 1/480 (лучше 1/960) + ISO/WB/EV lock **до** shutter/start; предварительно подтвердить, что локи доступны именно в 4K 8:7@59.94 по Open GoPro и переживают старт записи (верифицировать по метаданным файла) — HTTP при записи хрупок.

**Д. Декодер:** (10) temporal-модель: Theil-Sen фит idx(n) с наклоном ≈1.001, отброс residual >0.5 — выбросы ±7 мс исчезают по построению; (11) seam-фаза в rows-режиме на полном кадре (без downscale до 1280); **обязательная калибровка**: гомография экран→камера (fisheye, угол) + измерение времени и направления вычитки роллинг-шаттера сенсора в 8:7 (LED-мигалкой, ~8–16 мс) — без неё формула seam_row×(16.67/строки) неверна; (12) фаза дубля = фит рампа с линейным дрейфом.

**Е. Критерий приёмки стенда:** два подряд дубля одной камеры — согласованная фаза, SE < 0.3 мс.

## 2. Rejection-идея: условно жива — «смерть» была ошибкой неполноты знаний, но воскрешение не доказано

**Что подтверждено:** kill-аргумент опирался на ложную посылку «кадры сенсора = только файл». На HERO12/13 live preview во время записи существует **штатно** (восстановлен после спора с Contour; функция признана патентно чистой — GoPro в мае 2026 избежала выплаты $8.2M, claim invalidated; Quik делает превью-при-записи по WiFi). Фаза читается из **содержимого** кадра (абсолютный индекс полосы + позиция границы роллинг-шаттера), поэтому задержка/декимация/транскод стрима неважны.

**Что НЕ подтверждено:** работает ли именно `/gopro/camera/stream/start` **одновременно с encoding по USB** на HERO13. Против: issue #352 (H11 Mini: shutter/start убивает превью; открытый feature request), #622 (H13 fw 01.12: stream/start молча не стартует — причина неизвестна, версия «HEVC» — спекуляция). Webcam-режим мёртв по построению (эксклюзивен, нет записи на SD). HDMI Media Mod — живой запасной канал (Live View работает при записи), но только как верификатор на 1–2 камерах.

> ✅ **УЖЕ ПОДТВЕРЖДЕНО ЖИВЫМ ТЕСТОМ (2026-07-13, наша HERO13, USB NCM, 4K 8:7@59.94):** стрим запущен ДО записи продолжает идти ВО ВРЕМЯ encoding — 1013 UDP-пакетов / 1164 КБ за 3 с (idle: 699/812). Главный блокер раздела снят; остаются шаги 1, 3 (обратный порядок stream-после-start), 4, 5, 6 протокола E14. Windows-ловушка: ffprobe режется файрволом — принимать python-сокетом.

**Решается бесплатным экспериментом E14 (полдня, СЕГОДНЯ, до любых покупок), на одной HERO13:**
1. **Gate:** стенд починен по разделу 1 (без зелёного стенда результаты не засчитываются) + **лок экспозиции обязателен** (shutter 1/240, ISO/WB lock) — иначе сравнение фаз невалидно.
2. `stream/start?port=8554` по USB; первым делом tcpdump/socat: приходят ли UDP-пакеты вообще (отделить «камера не шлёт» от «не декодируется»); попробовать keep-alive.
3. При живом превью — `shutter/start` в 4K 8:7@59.94: падает ли стрим (статусы 8/32/55). Если падает — **обратный порядок**: сначала запись, потом stream/start (другой кодовый путь, главный тест).
4. Негативный контроль канала: читается ли 48-ячеечная полоса из 480p-превью через fisheye под углом с yield >80%; если нет — грубая полоса 8–12 ячеек или LED-линейка (иначе E14 провалится по каналу измерения, а не по сути).
5. 10 коротких дублей: |phase_preview − phase_file| < 0.5 мс на всех → превью = кадры сенсора, kill-аргумент официально мёртв.
6. Безопасность: stream/stop при записи не роняет файл; 5-мин дубль с 3 циклами старт/стоп превью; стресс поллинга минимум на 3 камерах одновременно.

**Схема на 100 камер (если E14 зелёный):** все стартуют запись → превью пачками по 3–5 с (N параллельных стримов измерить пилотом на 3–5 камерах) → декод фазы → «промазавшие» получают stop+start (цикл ~10–12 с с учётом enc_delay 3.08 с) → повтор. Окно ±2 мс (p≈0.24): ~17–19 раундов, но с серийностью замеров **реальная калибровка 10–20 мин**, не 4 (прежняя оценка занижена в 3–5 раз). Окно ±1 мс: ~36–40 раундов. Среднее число стартов на камеру: 4.2 / 8.3.

**Три условия до ставки на схему:** (а) E13 обязателен ДО — если фаза=f(момента старта), рестарты по скрипту дадут коррелированные фазы и часть камер «застрянет»; проверить гистограмму фаз на равномерность, fallback — рандомизированный джиттер момента shutter/start; при детерминизме отбор заменяется прицельным таймингом (тогда достижимо 1/20–1/60 кадра); (б) дрейф ppm мерить **как функцию времени записи/нагрева** (полоса в начале и конце 5-мин дубля на 2–3 камерах), не одной константой — камера греется в 4K 8:7; компенсация упреждением −drift·T/2 или дубли ≤2 мин; (в) 1/100 кадра чистым отбором недостижим (p≈0.02) — только через детерминизм E13.
