## Вывод ресёрча (2026-07-12, уверенность высокая/средняя)

Стоковый Timecode Sync HERO12/13 — это открытый QR-механизм Labs-языка `oT`. Камера НА СТОКОВОЙ прошивке сканирует QR любого генератора при строгом полном формате:

```
oT<YYMMDDHHMMSS.mmm>oTD<0|1>oTZ<±минуты зоны>
пример (dnewman, GoPro): oT231108082611.785oTD0oTZ-8
```

- Подтверждение третьей стороной: **Tentacle Timebar** «GoPro HERO 12 and 13 supports this QR code timecode out of the box» (https://support.tentaclesync.com/hc/en-us/articles/14434205852957); их приложение бесплатно, но требует Tentacle-железо как источник TC — потому пишем СВОЙ генератор.
- Формат: gopro/labs discussion #640 + https://gopro.github.io/labs/control/tech/ (исходники генераторов — публичный репо gopro/labs).
- Ограничение стока: frame-rate-команда через QR НЕ поддерживается (только Labs); камера берёт лишь время/TC.
- Латентность «скан → применение» различается между моделями (labs#830: ~6 кадров разницы Hero11/12); на стоке TCAL-калибровки нет → оффсет мерить нашим стендом.

## Значение для проекта

Автономный ресинк часов ста камер с одного монитора/проектора БЕЗ телефона и БЕЗ обязательной Labs — снимает главную зависимость стратегии ±1 кадр от операторского гейта прошивки. Labs остаётся желательной (TCAL, `!S`, USB Power Trigger), но не критичной.

## Реализация

`src/qr_time.py` — fullscreen-генератор анимированного oT-QR (обновление каждый кадр, лог показанных payload'ов с QPC).

## Проверка на камере (когда USB поднимется)

1. Камера смотрит на монитор с `qr_time.py`; ждать иконку QR-скана на камере (или 20 с).
2. Записать 5 с клипа → ffprobe TC-трек (`tmcd`) → сравнить со временем стенда в кадре.
3. Повторить 10×: распределение «QR-время → TC-трек» = оффсет+σ канала.
Статус: **не выполнено** (E0-блокер драйвера).
