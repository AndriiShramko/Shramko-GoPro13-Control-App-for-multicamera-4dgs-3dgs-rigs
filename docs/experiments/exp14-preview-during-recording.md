# E14-пилот: превью-стрим РАБОТАЕТ во время записи (2026-07-13)

Живой тест на HERO13 (4K8:7@60): `/gopro/camera/stream/start?port=8554` → UDP MPEG-TS.
- IDLE: 699 пакетов / 812 КБ за 3 с.
- **ВО ВРЕМЯ ЗАПИСИ (encoding=True): 1013 пакетов / 1164 КБ за 3 с — стрим не прерывается.**
- Windows-ловушка: ffprobe блокируется файрволом (I/O error), python-сокет — нет. Для чтения стрима либо правило файрвола, либо принимать сокетом и скармливать декодеру пайпом.

СЛЕДСТВИЕ: kill-аргумент против rejection-фазировки («замер фазы требует остановки записи») ОПРОВЕРГНУТ живой камерой. Оператор был прав, потребовав перепроверку.

Осталось доказать (E14 полный, одна камера):
1. Кадры превью = кадры сенсора (та же фаза)? Превью 856×480, вероятно сабсемпл — прочитать полосу/LED из превью и СРАВНИТЬ фазу с фазой одновременно записанного файла. Совпадение = превью-фазометр валиден.
2. Хватает ли разрешения превью для Manchester-полосы (полоса на весь экран / LED-бар крупнее).
3. Нагрузка: стрим+запись+HTTP — не роняет ли камеру на длинном дубле.
