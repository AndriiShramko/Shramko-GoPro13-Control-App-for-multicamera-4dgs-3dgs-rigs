# gopro-genlock — spec-experiments: протокол Фазы 0 (+ red-team фиксы)

Роутер: [[spec]]. Все 24 замечания red-team 2026-07-12 вшиты (номера в скобках). **Это чек-листы проверки, НЕ сценарий выполнения** — порядок и способ агент выбирает сам, кроме E0-первым.

## Два трека (red-team #1 — снятие Labs-контрадикции)

- **Трек A (сток)** — ВСЕ DONE-критерии Фазы 0 выполнимы на стоковой прошивке. Labs не является зависимостью.
- **Трек B (Labs, опционально)** — агент готовит оператору кейс: что даст Labs (Precision Time QR с монитора = автономный ресинк ±1 кадр, `!5S` отложенный старт, USB Power Trigger, TCAL). Флешить ТОЛЬКО после явного «да» и В КОНЦЕ Фазы 0 (#19 — не рисковать единственной камерой до снятия стоковых данных).

## E0 — Connectivity gate (ПЕРВЫМ, ≤15 мин чистого времени; #2)

`GoPro Connect` в меню камеры (инструкция оператору заранее) → ipconfig/IP → `wired_usb?p=1` → `/state` → запись 5 с → download 1 файла. **Go/no-go**: канала нет → диагностика драйвера NCM (см. [[spec-ops]]) → blocker-отчёт. База доков и всё остальное — ПОСЛЕ гейта.

## Цепочка измерений (measurement chain; #4)

Эталон времени рана = **QueryPerformanceCounter (QPC)** хоста. Цепочка: QPC → машиночитаемый счётчик на экране → кадры MP4 → GPMF (STMP/CORI) → TC-трек. На время тестов w32tm-синхронизацию отключить или логировать её события (NTP-степ посреди дрейф-теста = мусор). Set/read часов камеры по HTTP имеет СЕКУНДНУЮ гранулярность — только для грубых проверок, не для мс-измерений.

**Счётчик — не OCR-цифры** (#15): основной канал = машиночитаемая кодировка (крупные бинарные/Gray-блоки, номер кадра стенда + QPC-таймстемп), цифры рядом для человека. Декодер валидируется на эталонном клипе с известным содержимым ДО использования в экспериментах.

**Стенд**: весь измерительный блок — в центральной safe-zone под самый узкий FOV из тестируемых режимов (#12); автопроверка кадрирования по первому клипу каждого режима, фейл → стоп и вызов оператора. Полосные/вспышечные тесты — в затемнении (комнатный LED/люминесцент мерцает 100 Гц; #11).

## Эксперименты Трека A

- **E1 Джиттер старта** (N≥30): USB `shutter/start`, момент команды по QPC vs первый кадр счётчика. Framing ЧЕСТНЫЙ (#10): дисплей-латентность (DWM/input lag 20–50+ мс) неизвестна и плавает → отчёт = ОТНОСИТЕЛЬНЫЕ величины и джиттер (σ, min/max, гистограмма), не абсолют.
- **E2 Дрейф** (≥20 мин, профиль 1080p30 + мониторинг флага Hot, принудительный стоп при warning, cooldown 10–15 мин; #7): позиция счётчика в кадрах начало/середина/конец → ppm + CI; повторить холодной/прогретой камерой. Итог: цепочка QPC↔кадры↔GPMF в отчёте.
- **E3 Характеризация монитора + STMP** (#3, #4): камера в профиле B (2.7K240) снимает монитор → направление/скорость scanout, pixel response; эксперимент «прибить семантику STMP» против счётчика. **T_readout экранной вспышкой НЕ меряется** (LCD: scanout 16.7 мс + response 5–15 мс >> суб-мс фронт) — допустима только low-confidence оценка с честной пометкой; точное измерение = LED/Arduino → shopping-list Фазы 1.
- **E4 Стабильность аудиоканала** (переименовано из «валидации»; #18): ни экран, ни WASAPI не эталон → меряем взаимный джиттер аудио-vs-экран и повторяемость внутреннего A/V-офсета. Клапы: ОДИН визит оператора = одна запись с 20 клапами подряд в кадре по инструкции-скрипту (#6); дистанцию рулеткой — один раз при настройке стенда.
- **E5 Часы камеры** (грубо): set/read RTT N≥20 — для протокола, с пометкой «секундная гранулярность».
- **E6 Quik TC QR** (#9): проверить, существует ли воспроизводимый генератор стокового Timecode-Sync-QR вне Quik; нет → путь честно помечается «operator-assisted (телефон)».

Power-state перед каждым тестом логируется; auto power-off выставлен через API в E0; серии батчатся, keep-alive держится (#8). Помнить: умершую камеру по USB НЕ включить (сток) — это стоп до оператора.

## Verify-скрипт = часть DONE (#5, анти-фальсификация)

`tools/verify_phase0.py`: пересчитывает ВСЕ заявленные статистики из сырых MP4 в `captures/` (manifest с checksums, каждая строка CSV ссылается на файл/кадр, число строк ≥ N эксперимента). DONE-критерий считается выполненным ТОЛЬКО если verify проходит на чистом прогоне. Каждое число в отчётах — с σ и пределом метода.

## Gate Фаза 0 → Фаза 1 (#21, пороги задать ДО измерений)

Дефолтные пороги (агент уточняет по факту, изменения — с обоснованием в vault): джиттер старта σ ≤ 2 кадра @30fps — иначе стратегия «триггер+обрезка» пересматривается; дрейф стабилен per-camera (повторные измерения ppm расходятся < 5 ppm) — иначе per-take калибровка обязательна; декодер счётчика ≥ 99% кадров; полный цикл record→download→analyze автоматизирован без ручных шагов.

## Протокол Фазы 1 (2+ камер, следующий ран — написать, не исполнять)

Парный офсет тремя методами в одном дубле (chirp равноудалённой колонкой / LED-вспышка → полосы RS / счётчик); статистика фазы сенсора по power-cycle (20 циклов); гипотеза «общий рубильник питания»; парный дрейф 30 мин (chirp каждые 30 с) → стабильность ppm per-serial; сквозной мини-пайплайн: TC+аудио (целые кадры) → LED (субкадр) → ретайминг → контроль вспышкой в конце. Shopping-list: Arduino + LED (наносек. фронт), опц. LED-часы по чертежу RocSync, powered USB-хабы, 240 Гц монитор (если нет).
