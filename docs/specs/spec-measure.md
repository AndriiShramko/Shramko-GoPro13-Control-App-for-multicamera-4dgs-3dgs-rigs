# gopro-genlock — spec-measure: модель рассинхрона и методы измерения

Роутер: [[spec]]. Наука 2026-07-12 (sync-science агент, источники внизу).

## Модель рассинхрона камеры i

`Δt_i(t) = A_i + B_i + Φ_i + D_i·t`

| Компонент | Природа | Что делать |
|---|---|---|
| A — задержка команды старта | BLE 40–160 мс разброс; USB ~20 мс | Мерить каждый способ (гистограмма) |
| B — внутренний старт записи | Случайный, НО меняет только ЦЕЛЫЕ кадры (старт не сбрасывает фазу сенсора — проверить в Ф1) | Обрезка на посте по TC/аудио |
| Φ — фаза сенсора | Free-running с включения; НЕУПРАВЛЯЕМА (нет API/genlock) | Только измерять и компенсировать на посте |
| D — дрейф кварца | 20–50 ppm + температура → **0.3–1 кадр за 10-мин дубль** | Маркеры в начале И конце дубля; модель «офсет+наклон»; ppm per-serial калибруется один раз (гипотеза) |

После power-cycle Φ рандомизируется; RTC переживает смену аккума, но ресинк часов обязателен.

## Лестница методов измерения

| Метод | Предел | Заметки |
|---|---|---|
| Монитор-счётчик | = refresh: 16.7 мс @60Гц, 4.2 мс @240Гц | rAF/pygame; проверка честности — монотонный номер кадра; input lag сокращается в относительных измерениях |
| Аудио clap/chirp + кросс-корреляция | 0.1–1 мс реально | 343 м/с = 2.92 мс/м! Колонка в центре кольца ИЛИ вычитать дистанции. Лог-свип 1–8 кГц 0.5 с устойчивее клапа. Нужна калибровка внутреннего A/V-офсета камеры (неизвестен публично — мерить) |
| **Вспышка + полосы rolling shutter** | **σ 0.3–0.5 мс (= путь к 1/100 кадра)** | Вспышка короче кадра → полоса строк; фронт полосы = субкадровая фаза: `t ≈ t_кадра + (r0/H)·T_readout`. Нужен LED (наносек. фронт); экранная вспышка размазана scanout+LCD → только грубо. T_readout HERO13 неизвестен per-mode — мерить (ориентир HERO10 4K60 ~8-10 мс) |
| LED-часы в кадре (RocSync) | 1.34 мс RMSE, проверено на GoPro 10/12 | Кольцо 100 LED (1 мс/позиция) + бинарный счётчик; чертёж DIY для рига — arXiv:2511.14948 |
| LTC в аудио | кадровая | См. [[spec-api]] |

**Запреты методики**: HyperSmooth/EIS OFF (иначе строки переставлены); выдержка короткая (1/480+) для узких полос; fps в анализе — точные рациональные (29.97/59.94); НЕ доверять «бип колонок + вспышка экрана» как эталону одновременности (WASAPI 10–30 мс нестабильно) — эталон = физическое событие (клап) или Arduino (LED+пьезо на одном пине); все измерения ОТНОСИТЕЛЬНЫЕ (камера-vs-камера), не абсолютные.

## Стратегия синхронизации (сводка prior art)

1. **±1 кадр**: Labs Precision Time QR перед дублем (±1 кадр пока не выключали) + одновременный USB-триггер + **обрезка на посте по TC/аудио** → требование к старту смягчается до «в пределах секунды». Так жили DyNeRF (21×GoPro) и bullet-time индустрия.
2. **Субкадр (1/10→1/100)**: измерение LED-вспышкой (полосы RS) в начале+конце дубля → компенсация: (а) VFI-ретайминг на общую сетку (RIFE/minterpolate; риск артефактов на быстром движении — тестировать), (б) per-camera time offset прямо в 4DGS (Sync-NeRF, SyncTrack4D <0.26 кадра; измеренные офсеты = init/prior).
3. **Управлять фазой нельзя** (libsoftwaresync-подход непереносим — нет API). «Общий рубильник питания» — дешёвая непроверенная гипотеза (#1101), эксперимент Фазы 1.

## Достижимость целей (честно)

- ±1 кадр — ДА (QR+триггер+обрезка).
- 1/10 кадра (3.3 мс @30fps) — измерить: да (3 метода); компенсировать: ретайминг/4DGS-офсеты.
- 1/100 кадра (0.33 мс @30fps) — измерить: только LED+RS-полосы (усреднение серии вспышек); управлять: НЕЛЬЗЯ в принципе; компенсация только на посте.
- Дрейф: на 10-мин дубле 0.3–1 кадр → маркеры в начале и конце каждого дубля обязательны.
