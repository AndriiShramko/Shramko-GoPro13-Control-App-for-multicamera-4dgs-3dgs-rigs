**Рекомендация агента: ДА, в конце Фазы 0** (после снятия всех стоковых данных, чтобы сравнить «до/после» и не рисковать единственной камерой до этого).

**⬆ Апдейт после вводной «на площадке только USB, без QR» (2026-07-12): вес кейса вырос.** Labs «Command Shell via USB Comms» — единственный известный путь слать `oT` (мс-часы) и `!S` (отложенный старт) ПО КАБЕЛЮ. На стоке USB-часы = 1 секунда. Детали: docs/methodology/sync-strategy-usb-first.md.

## Что даёт Labs v2.10.70 для нашей задачи (источники в docs/api/labs.md)

1. **Precision Date & Time QR** — главный инструмент ±1 кадра: анимированный QR с мс-точностью, показывается С МОНИТОРА → агент ресинхронизирует камеры сам, без телефона; заявлено ±1 кадр, пока камеры не выключались. На 100 камерах — один большой экран/проектор на группы камер.
2. **`!5S` / `!20:00S` отложенный старт** — старт записи по времени часов камеры, а не по HTTP-команде → потенциально убирает USB-джиттер из уравнения старта (проверяемо в Ф1: сравнить E1-распределение против QR+`!S`).
3. **TCAL** — калибровка хода часов (± мс/период) — прямой инструмент компенсации per-serial ppm из E2/P4.
4. **USB Power Trigger** — автовключение при подаче питания: на площадке 100 камер поднимаются рубильником, без 100 нажатий кнопки.
5. **LTC по аудиовходу** (с Media Mod) и GPS-sync — запасные каналы, пока не нужны.

## Риски / стоимость

- Прошивка официальная (gopro.github.io/labs), обратимая на сток; риск кирпича низкий, но камера у нас ОДНА — потому и «в конце фазы».
- Labs-версии выходят с задержкой после стоковых; фичи вне гарантийного мейнстрима.
- Для 100 камер прошивку Labs нужно будет накатить на каждую (процедура через SD-карту, батчится).

## Что агент сделает после «да»

Скачает официальный Labs-образ для HERO13, подготовит SD (инструкция для оператора — вставить/включить), проверит версию после прошивки, прогонит E1-повтор с QR-ресинком и `!S`-стартом, сравнит распределения со стоковыми. Сам факт прошивки — руками оператора по инструкции (гейт спеки).
