# Windows и NCM-драйвер GoPro — известная проблема и два способа лечения

HERO13 по USB — это сетевой интерфейс класса CDC NCM (VID 2672). Linux/macOS поднимают его из коробки
(cdc_ncm); **Windows — нет**, и это блокер всего HTTP-over-USB канала.

## Наша диагностика (эта машина, 2026-07-12)

Полный лог: `docs/session-logs/2026-07-12-E0-connectivity-gate.md`. Кратко:

1. Камера видна как композит `VID_2672&PID_0059` (серийник C3531325121539): USB Composite — OK,
   `HERO13 Black` (WPD/медиа) — OK, **`CDC NCM` — Error, ProblemCode 28** («драйверы не установлены»).
2. Инбокс-драйвер Windows не привязывается **by design**: `C:\Windows\INF\usbncm.inf` матчит только
   `USB\MS_COMP_WINNCM`; универсальная строка `USB\Class_02&SubClass_0d&Prot_00` в inf **закомментирована**.
3. Камера **не заявляет MS-OS-дескрипторы** (`UsbFlags\267200590001\osvc = {0,0}`) → автопривязка
   невозможна в принципе, это не глюк кэша.
4. Пакет инбокс-драйвера в системе ЕСТЬ (`DriverStore\...\usbncm.inf_amd64_...`) → ручная привязка возможна.
5. Фирменный «GoPro UsbNcm Host Device» отсутствует в DriverStore и в Microsoft Update Catalog;
   официальный носитель — установщик **GoPro Webcam utility**; его хостинг (salesforce) отдаёт файл только
   интерактивному браузеру, curl получает заглушку. Сторонние зеркала отвергнуты как недоверенные.
6. Привязка драйвера требует админа (`pnputil /restart-device` → Access denied из неэлевированного шелла).
7. Ожидаемый IP этой камеры после драйвера: **172.25.139.51** (серийник ...539), хост получит `.54`.

## Внешнее подтверждение — OpenGoPro issue #384

https://github.com/gopro/OpenGoPro/issues/384 — та же картина на HERO10/Win10: устройство «CDC NCM»
висит в «Other Devices» без драйвера, `http://172.2x.1yz.51:8080/...` недоступен (на macOS работает).
Решение от KonradIT (contributor): **«Install GoPro Webcam for windows»** — автор подтвердил:
«That was it thank you!». Т.е. проблема давняя, классовая (не специфика HERO13), решение известно.

## Способ A — ручная привязка инбокс-драйвера (рекомендуем: ~2 мин, ничего не качать, нужен админ)

1. Device Manager → устройство «CDC NCM» с жёлтым восклицательным знаком.
2. ПКМ → Обновить драйвер → Найти на этом компьютере → **Выбрать из списка**.
3. Класс «Сетевые адаптеры» → производитель **Microsoft** → модель **«UsbNcm Host Device»** → Далее.
4. Согласиться с предупреждением о совместимости (это стандартный CDC NCM).
5. Проверка: в «Сетевых адаптерах» появился адаптер, `ipconfig` показывает подсеть `172.2x.x.x`.

## Способ B — GoPro Webcam utility (если A не взлетел)

В интерактивном браузере: community.gopro.com → статья «GoPro Webcam Information And Troubleshooting» →
секция Windows → «Download the GoPro Webcam desktop utility» → установить (несёт драйвер
«GoPro UsbNcm Host Device») → перезоткнуть USB камеры.

## Замечания для масштабирования на риг

- Привязка драйвера — **per-device-instance**? Проверить: после способа A вторая камера (другой серийник)
  может снова потребовать ручную привязку — TODO-verify на 2+ камерах. Если да — способ B (класс-драйвер
  GoPro) может оказаться удобнее для 100 камер, либо предпривязка через `pnputil /add-driver`.
- На этой машине в UsbFlags есть след `26720056` (другая GoPro, PID_0056) тоже без драйвера —
  проблема воспроизводится на всех PID.
- Каждая камера = отдельный NCM-адаптер со своей подсетью `172.2X.1YZ.0/24`; IP камер брать из
  gateway каждого адаптера (см. usb-wired-control.md).
