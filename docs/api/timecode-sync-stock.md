# Стоковый Timecode Sync HERO12/13 (Quik QR) — без Labs

## Механизм

Штатная функция прошивки HERO12/13 (Labs не нужен): приложение **GoPro Quik** показывает
**динамический (анимированный) QR**, камера наводится на экран телефона → на камере появляется
«Time code has been updated». Повторить для каждой камеры рига.

Порядок в Quik (по walkthrough GIGAZINE): меню → «Timecode sync» → показать QR каждой камере.
Аккаунт GoPro не обязателен («Continue as a guest»).

## Формат QR (важно: это тот же oT-язык, что в Labs)

Из ответа dnewman-gpsw (GoPro) в gopro/labs discussion #640 — стоковая прошивка HERO12 требует
строгий формат «time, daylight savings, zone info»:

```
oT231108082611.785oTD0oTZ-8
```

- Поле времени содержит **миллисекунды** (`.785`).
- Сток строже Labs: обязательны все три части (время + DST + зона) одной строкой; QR старого формата
  (только `oT...`) сток отвергает — из-за этого сторонние генераторы (кейс UltraSync Blue slate)
  несовместимы. Под Labs «timecode is more flexible».
- Следствие: зная формат, QR можно генерить и показывать с монитора без Quik — но именно для стока
  это НЕ подтверждено экспериментом (примет ли камера QR не из Quik) — TODO-verify-on-camera.

## Что получается в файлах

- Камера пишет **TC-трек в MP4** (timecode track), который читают NLE: GIGAZINE демонстрирует
  multicam-сборку в Premiere Pro по этому таймкоду без хлопушек и доп. оборудования.
- Это синхронизация **метаданных**, НЕ genlock: фаза сенсора free-running, затворы камер не выровнены
  (подтверждено D. Newman и Xangle — spec-api, high). Для 4DGS это значит: TC даёт выбор ближайшего
  кадра (±полкадра), остальное — пост-выравнивание по GPMF (см. media-gpmf.md).

## Точность и дрейф

- Команда несёт мс-поле, но реальная точность ограничена задержкой «камера увидела QR → записала часы».
  Tentacle (поддержка Timebar) отмечает эту латентность и компенсирует её оффсетом в QR.
- Оценка ресёрча spec-api: **<50 мс** между камерами (med) — TODO-verify-experiment (мигающий LED / хлопок).
- Дрейф: заметен после **60-90 мин** → пересинхронизация перед каждым дублем/сессией (spec-api, med;
  внутренние часы GoPro ~42 ppm — см. spec-api).

## Ограничения для нашего рига

- **Нужен телефон с Quik** и ручной проход по всем камерам → на 100 камер плохо автоматизируется
  и не скриптуется с хоста.
- Точность ниже, чем у Labs Precision Date & Time QR (аним. QR с TCAL-калибровкой, показывается
  с монитора, без телефона) — поэтому базовый план проекта = Labs, а стоковый Timecode Sync =
  fallback, когда Labs ставить нельзя (камеры не наши / операторский гейт не пройден).

## Сравнение вариантов синхры часов

| Способ | Прошивка | Телефон | Автоматизация | Точность |
|---|---|---|---|---|
| Timecode Sync (Quik QR) | сток HERO12/13 | нужен | нет | <50 мс (med, TODO-verify) |
| Precision Date & Time QR | Labs | не нужен (монитор) | да | ±1 кадр (med-high, TODO-verify) |
| LTC аудио | Labs + Media Mod/Mic Adapter | нет | да, но дорого/камера | субкадровая, jam ~1 ч |
| `set_date_time` HTTP | сток | нет | да | только секунды — не годится |
