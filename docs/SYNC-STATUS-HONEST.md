## ТРЕБУЕТ 2-Й КАМЕРЫ (Фаза 1) — на одной физически не измеримо

- **Сравнение `!S` vs HTTP-триггер по КУЧНОСТИ старта.** Ключевой факт: точность старта на ОДНОЙ камере — не тот вопрос. Важна ДЕЛЬТА между камерами, стартовавшими одинаково. На одной камере число дельты не существует. `!S` функционально срабатывает (старт по часам камеры), но лучше ли он одновременного HTTP-триггера — покажет только пара камер.
- Субкадровая ФАЗА между камерами (по вспышке/полосам).
- Стабильность дрейфа per-serial (калибруется ли ppm раз и навсегда).

## ФИЗИЧЕСКИ НЕВОЗМОЖНО (доказано GoPro + литература, не нами)

- **Управлять фазой кадра командами.** Сенсор free-running с включения; ни `!S`, ни таймкод, ни QR не сдвигают момент экспозиции. → таймкод/отложенный старт дают МАКСИМУМ ±1 кадр, НЕ внутрикадровую синхру. **Это и есть причина, почему прошлые попытки Андрия с часами/отложенным стартом «не давали синхрон» — они и не могли дать субкадр, это ограничение платформы, а не ошибка настройки.**

## ГДЕ РЕАЛЬНО ЛЕЖИТ 1/10–1/100 КАДРА (два пути, оба не через команды старта)

1. **Путь А — измерить фазу вспышкой и скомпенсировать на посте (ГАРАНТИРОВАННЫЙ).**
   Общая вспышка на площадке (одна на все камеры) → полосы rolling shutter → фаза каждой камеры с σ 0.3–0.5 мс (Šmíd&Matas, открытый код) → компенсация ретаймингом или per-camera offset в 4DGS (Sync-NeRF/SyncTrack4D). Это НИКОГДА не пробовалось Андрием — потому и не «не получилось». Железо: дешёвый спидлайт + Arduino-триггер.
2. **Путь Б — управлять фазой моментом ПОДАЧИ ПИТАНИЯ (ставка, никем не проверено).**
   Labs USB Power Trigger: камера стартует при подаче VBUS. Если лаг «питание→фаза сенсора» стабилен — фазой можно УПРАВЛЯТЬ точным реле (Arduino+MOSFET, мкс). Проверяется в Ф1 (E7b). Ресёрч предупреждает: джиттер загрузки может быть сотни мс → тогда путь Б только для staggered-boot, не для фазы. Данные решат.

## Рабочая схема площадки (текущая лучшая гипотеза)

Стоковый NCM-режим для управления + QR-ресинк часов с монитора/проектора (±1 кадр) + `!<время>S` синхростарт по часам (кучный старт, транспорт не важен) + **общая вспышка в начале и конце дубля** для субкадровой фазы → компенсация на посте. Аудио — грубый кросс-чек ±1 кадр. Serial-шелл НЕ в боевом цикле (ломает NCM-драйвер Windows; годится для разовой конфигурации). На 100 камер — Linux-хосты (нет драйверной боли) + программируемые USB-хабы (uhubctl) + камеры без аккумуляторов на USB Power Trigger.
