# 4K 8:7@60: encoding стартует через ~3.1с после команды (стабильно!)

Все дубли E9 выходили 0.6-1.0с при команде «пиши 4с». Скачивание исправно (size-verify), режим верифицирован. Причина: **в 4K 8:7@60 камера отвечает на shutter/start за ~90мс (HTTP 200), но encoding=1 поднимается только через ~3.1с** — sleep(4) съедался задержкой, реальная запись = остаток.

Измерено (3 пробы): 3.06 / 3.11 / 3.09 с — **разброс ~50мс, задержка СТАБИЛЬНАЯ**. В других режимах (5.3K дефолт) задержка близка к нулю — контрольные клипы были полными.

Значение для проекта:
1. **Латентность старта зависит от РЕЖИМА.** E1 (σ=18мс) мерил джиттер в дефолтном режиме — для боевого 8:7@60 старт-задержку надо мерить отдельно (и она ~3.1с!).
2. Стабильность (~50мс разброс на первых пробах) — потенциально хорошая новость для одновременного старта 100 камер: если у всех задержка одинакова, она компенсируется константой. Требует статистики (n=10+, разные камеры).
3. Любой эксперимент/продакшен-код обязан отсчитывать длительность записи от `encoding=1`, не от команды.
