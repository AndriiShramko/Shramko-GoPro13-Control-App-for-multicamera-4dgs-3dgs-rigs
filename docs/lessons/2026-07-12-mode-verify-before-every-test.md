# Перед КАЖДЫМ тестом — ставить и СВЕРЯТЬ режим камеры (E9 ушёл на 120fps)

Прогон E9 «на 8:7@60» реально записался в **5.3K@120** (ffprobe: 5312×2988@119.88): диагностика перед ним грузила дефолтный пресет и сбросила режим, а эксперимент поверил текущему состоянию. meta.json даже записал правду (res=100, fps=1) — но её никто не проверил. Оператор поймал по клипам.

**Правило: эксперимент сам приводит камеру в требуемый режим и отказывается бежать, если камера его не подтвердила.**

Механика (вшита в exp_phase_determinism.py):
1. `set_group?id=1000` → `presets/load?id=0` → set 2=108, 234=5, 3=5 (порядок важен).
   ⚠️ В «чужом» пресете (напр. id=1 Slo-Mo) video-настройки отвечают **403** — сначала load preset 0.
2. Верификация: state() обязан вернуть ровно WANT; 3 ретрая; иначе abort (гейт уже спас один невалидный прогон).
3. В анализе fps берётся из САМОГО клипа (cv2 CAP_PROP_FPS); несовпадение с ожидаемым > 0.5 fps → дубль invalid с пометкой.

Урок: «я выставил режим час назад» ≠ «камера сейчас в этом режиме». Пресеты сбрасываются загрузками/перепрошивкой/руками. Настройки в отчёте эксперимента — обязательное поле.
