# HTTP камеры ХРУПОК во время записи 4K8:7@60 (RemoteDisconnected) + самостоп записи при смерти клиента

Симптомы-матрёшка (стоили трёх прогонов E12):
1. Опрос `/gopro/camera/state` во время АКТИВНОЙ записи в тяжёлом режиме → камера рвёт соединение (`RemoteDisconnected`), скрипт падает.
2. Со скриптом умирает keep-alive → камера через несколько секунд САМА останавливает запись → клипы 19.4с вместо 60с.
3. Отдельно: fullscreen-стенд может быть перекрыт/убит на общей машине → камера снимает чужие окна → декод 0. ПРОВЕРЯТЬ КАДР ГЛАЗАМИ (ffmpeg -ss 5 -frames:v 1) до анализа.

Правила:
- Во время записи опрашивать state РЕДКО (≥10с) и в try/except; обрывы — норма, не ошибка.
- shutter_stop — с ретраями (до 10) после записи.
- В E9 не падало: 4с записи без опросов. Значит HTTP-управление на 100 камерах при активной записи планировать как «команда-и-молчание», без телеметрии в ходе дубля.
- Live-проверка стенда перед экспериментом: свежий лог растёт + процесс жив + (в идеале) контрольный кадр.
