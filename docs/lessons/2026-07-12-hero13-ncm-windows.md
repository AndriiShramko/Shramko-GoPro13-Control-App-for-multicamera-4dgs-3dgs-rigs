# HERO13 на Windows 10: NCM-интерфейс не биндится сам, и это не чинится без админа

Диагностическая цепочка, которая закрывает вопрос быстро (вся — без админа):
1. `Get-PnpDevice | ? InstanceId -match 'VID_2672'` → композит: NCM(Error 28) + WPD(OK) = камера в GoPro Connect, канал есть, драйвера нет.
2. `C:\Windows\INF\usbncm.inf` матчит только `USB\MS_COMP_WINNCM`; generic-строка `Class_02&SubClass_0d` закомментирована Microsoft-ом.
3. `HKLM\...\UsbFlags\<vidpid+rev>\osvc = 0,0` → камера НЕ заявляет MS-OS-дескрипторы → автопривязка невозможна в принципе (не кэш-глюк).

**Пути решения (оба через оператора/админа):** (A) ручная привязка инбокс «Microsoft → UsbNcm Host Device» через Диспетчер устройств («выбрать из списка»); (B) официальный установщик GoPro Webcam utility (несёт GoProUsbNcm; скачивается только интерактивным браузером с gopro.my.salesforce.com — curl получает Lightning-заглушку; bit.ly-ссылки из старых статей мертвы, 410).

**Для 100-камерного рига:** драйверная привязка по VID/PID делается один раз на хост — но проверять на КАЖДОМ новом хосте до площадки. Linux-хосты снимают проблему целиком (cdc_ncm из коробки).
